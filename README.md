# SnapLingo · 截图翻译

按下快捷键 → 框选屏幕上的任意文字 → 自动 OCR → 自动翻译 → 结果卡片。

SnapLingo 是一个 Windows 桌面小工具，常驻托盘，**启动快、内存占用低**（Tauri 2 + WebView2，无 Electron）。
默认是「Windows 内置 OCR（离线、免费、不需要 Key）+ 百度翻译（填 APP ID 与密钥即可）+ 目标语言智能判断」，启动后只在托盘，不会弹窗打扰；
识别引擎可在四种之间切换：Windows 内置 OCR、**本地 OCR 服务**（Umi-OCR 等，图片不出本机）、**视觉大模型**（一条请求同时拿到原文和译文）、**由翻译渠道直接读图**（有道 / 百度 / 腾讯的一步图片翻译）。

## 功能

| 功能 | 说明 |
| --- | --- |
| 全局快捷键 | 默认 `Ctrl + Alt + Z`，可在设置中重新录制 |
| 多显示器框选 | 触发时**先冻结全部屏幕画面**再弹出选区，因此不会截到选区窗口自身，也不会因为背景刷新而错位 |
| 拖拽即识别 | 松开鼠标即开始识别；`Esc` 或右键取消；选区小于 4px 自动忽略；**再按一次快捷键**或托盘「取消本次截图」同样能取消 |
| 出错处理 | 任何失败都会**弹出结果窗口，右下角同时出现一张应用内的通知卡片**说明原因（点击卡片直接跳到日志页；可在设置里关掉这张卡片），结果窗口内置「重试」；网络请求失败自动重试 3 次（共 4 次尝试，只对超时 / 连接失败 / 429 / 5xx 这类可恢复错误重试），绝不静默失败 |
| 防卡死 | 每个耗时步骤都有硬超时（截图 15s、识别 30s、翻译 120s、一步图片翻译 90s、视觉大模型 120s、整体 150s）；框选 3 分钟未确认自动取消；若真的卡住（连续 4 分钟无响应）程序会自行退出，**绝不会让选区窗口把桌面锁死** |
| OCR | ① Windows 内置 OCR（`Windows.Media.Ocr`，离线、免费）② 视觉大模型（OpenAI 兼容 `/chat/completions`，图片以 base64 传入）③ 本地 OCR 服务（Umi-OCR 等本机服务，模型跑在自己电脑上）④ 一步图片翻译：由有道 / 百度 / 腾讯直接读图，本机不参与 |
| 翻译 | ① OpenAI 兼容接口（内置 22 家预设：NVIDIA NIM、智谱、DeepSeek、OpenCode Zen、百度千帆、腾讯混元、讯飞星火、Gemini、Groq、Mistral、xAI、Together、DeepInfra、Cerebras、Fireworks…）② DeepL（Free / Pro）③ 微软翻译（Azure）④ 谷歌翻译 ⑤ 有道智云 ⑥ 有道大模型翻译（子曰，Pro / Lite）⑦ 百度翻译（通用 / 大模型，支持 API Key 鉴权）⑧ 腾讯云翻译（TMT）⑨ 关闭（只 OCR 不翻译） |
| 一步图片翻译 | 有道 / 百度 / 腾讯支持「递交图片、一次拿回原文 + 译文」，在「识别引擎」下拉里直接可选；需在各家控制台单独申请该服务（未开通会自动回退到本机识别 + 文本翻译） |
| 结果窗口 | 无边框置顶卡片，首次弹出在当前屏幕正中、大小约为屏幕的一半；之后在本次运行内**沿用你上次拖出来的尺寸**（尺寸始终不超出当前屏幕；开启「自适应内容」时高度按内容收缩、宽度限制在 360–1600 px），也可在设置里打开「自适应内容」让高度跟着译文长短走；底部一排「原文 / 译文 / 对照」三态切换，随时只看一边或对照查看；复制、重新翻译、`Esc` 关闭、失焦自动关闭（可关） |
| 历史记录 | 本地保存最近 N 条识别结果，可搜索查看、单条删除或清空 |
| 自动更新 | 设置 → **更新**（或托盘「检查更新…」）：从 GitHub Release 读取最新版本，发现新版本时右下角卡片提醒；页面里**一个按钮**就完成「下载 + 安装」，下载时显示进度条与已下载/总大小，**切到别的页面或关掉设置窗口都不会中断**（下载在后台线程里跑，装完自动拉起安装程序）；已经下好的安装包会被复用，再点不会重新下载；GitHub 的下载域名连不上时，可以填一栏「下载加速前缀」（例如 `https://ghproxy.net/`）或直接「用浏览器下载」。启动后约 9 秒会在后台静默检查一次（可关）。更新源仓库可在设置里改 |
| 运行日志 | 内置日志页（托盘「查看日志…」或设置 → **日志**）：本地时间戳、**最新的在最上面**、按错误 / 警告 / 信息 / 调试筛选，逐次记录走的渠道、实际调用的方法 + 地址，**失败时连接口返回的响应体一起记下来**（排查签名 / 配额 / 语言问题时最有用）；每次截图还会打印 `截图计时`（抓屏 / 编码 / 框选层）与 `处理计时`（识别 / 翻译）两行，慢在哪一步一眼可见 |
| 其它 | 开机自启、深浅色主题（7 套调色板）、中/英文界面、结果字号、自动复制、自定义 Prompt、API Key 一键探测/模型列表拉取；设置窗口是**自绘标题栏**（跟随主题配色，右上角是最小化/最大化/关闭，标题栏左侧按钮可在「左侧栏 / 顶部标签」两种导航布局间切换） |

## 系统要求

- **Windows 10 1809+ / Windows 11（x64）**
- **WebView2 运行时**：Windows 11 自带；Windows 10 一般由 Edge 提供。若提示缺少，安装 [Evergreen WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/)。
- **OCR 语言包**（仅当使用 Windows 内置 OCR 时）：
  「设置 → 时间和语言 → 语言和区域 → 添加语言」，在对应语言的“可选语言功能”里勾选**光学字符识别**。
  中文简体通常随系统一起安装。设置页里的「检测 OCR 环境」按钮会列出当前系统已安装的识别语言。
- **构建环境**：Node.js 20+/22+、Rust stable（MSVC 工具链）、Visual Studio Build Tools（“使用 C++ 的桌面开发”）。

## 开发与构建

```bash
cd snap-lingo

# 安装依赖（npm 12 会拦截 postinstall，需放行 esbuild 的安装脚本）
npm install
npm install-scripts approve esbuild     # 仅 npm 12+ 需要；旧版本可跳过

# 开发模式（热更新，首次编译 Rust 需要几分钟）
npm run tauri dev

# 仅前端类型检查 + 构建
npm run build

# 打包成安装包（NSIS，输出在 src-tauri/target/release/bundle/nsis/）
npm run tauri build
```

> Rust 侧依赖（`xcap`、`image`、`reqwest`、若干 Tauri 插件）首次 `cargo` 编译需要联网下载。

## 使用

1. 启动后程序只存在于**系统托盘**（没有主窗口）。
2. 右键托盘图标 → **设置**，至少配置一项：
   - **OCR 引擎**在「OCR」页用下拉列表选，共四种：
     - `Windows 内置 OCR`：离线免费，无需 Key，开箱即用；
     - `视觉大模型`：把图片发给多模态模型，对艺术字 / 复杂排版更准，需要 OpenAI 兼容的接口地址 / Key / 模型；
     - `本地 OCR 服务`：连接本机运行的离线识别服务（推荐 [Umi-OCR](https://github.com/hiroi-sora/Umi-OCR/releases)，免费开源、解压即用），填 `http://127.0.0.1:1224` 即可，图片完全不出本机；
     - `由翻译渠道完成（一步图片翻译）`：把图片直接交给有道 / 百度 / 腾讯识别并翻译，本机不跑 OCR（需该渠道开通「图片翻译」服务）。
   - **翻译渠道**在「翻译」页用下拉列表选：OpenAI 兼容、DeepL、微软、谷歌、有道、百度、腾讯，或「仅识别不翻译」。选中一个渠道后只显示它需要的输入框，并给出官方申请地址；每个渠道的 Key 各存各的，互不串用。百度还能在 **通用文本翻译 / 大模型翻译** 之间选，腾讯可选 **大模型版 / 极速版**。
   - **大模型厂商**用同一页里的预设下拉选（NVIDIA、DeepSeek、智谱、OpenCode Zen…）：选中即填好地址与模型，**每家的地址 / 模型 / 密钥也是分开保存的**，切换厂商不会串用彼此的 Key。
   - 只想离线使用：`OCR = Windows 内置 OCR`（或 `本地 OCR 服务`），`翻译 = 仅识别不翻译`。
   - 想一条请求搞定：`OCR = 视觉大模型`，填好 OpenAI 兼容的地址/Key/模型；若开启 **一次调用**，则同一次请求同时返回原文与译文。
3. 用 `Ctrl + Alt + Z`、或托盘菜单「截图翻译」触发截图（单击托盘图标是打开**设置**，不会截屏）。
4. 拖拽框选文字区域，松开鼠标开始识别；`Esc` / 右键取消，再按一次快捷键也能取消。
5. 结果窗口出现后可：用底部「原文 / 译文 / 对照」切换要看的版本、复制、重新翻译、`Esc` 关闭；**截图图片显示在译文的上一行（整宽条带）**便于逐句比对，点一下图片可放大到整窗查看，也可以用底部的「截图」按钮把图片收起来。识别或翻译失败时，窗口会显示原因和「重试」按钮（重试会复用上一次的截图，不必重新框选）。
6. 托盘菜单里的「取消本次截图」和「退出 SnapLingo」在**任何时刻**都可用；退出时若 2.5 秒内没有正常结束，进程会被强制结束，不会留下关不掉的窗口。
7. 想知道某一次到底走了哪个引擎、请求发到哪个地址、参数与失败原因：托盘菜单「查看日志…」或设置里的 **日志** 页。它会实时读取 `%APPDATA%\SnapLingo\snaplingo.log`（本地时间戳，**最新的在最上面**），支持按 **错误 / 警告 / 信息 / 调试** 类型筛选、关键字过滤、复制或清空，并能一键打开日志文件所在位置。设置页每个渠道下方也会直接显示 **实际调用** 的 方法 + 地址（含档位说明）。
8. 新手建议先看 **使用手册**：设置 → **关于** → 「使用手册」按钮会打开随程序打包的 `docs/GUIDE.md`（从安装、各引擎配置到常见问题都有中文说明）。
9. 升级到新版本：设置 → **更新**（或托盘「检查更新…」）。页面会显示当前版本、GitHub 上的最新版本与更新说明；点「下载并安装」会把安装包下到临时目录，再点「立即安装并重启」，程序退出、安装程序接管，装完重新打开即可。启动后约 9 秒还有一次静默检查，发现新版本会用右下角卡片提醒你（卡片可直接点进来）。

### 发布新版本（维护者）

自动更新读的是 GitHub Release，所以发版时只有三件事：

1. 改版本号：`src-tauri/tauri.conf.json` 的 `version`（**这个是权威值**，安装包文件名与「当前版本」都取自它），同时把 `package.json` 的 `version` 改成一样。
2. `npm run tauri build`，得到 `src-tauri/target/release/bundle/nsis/SnapLingo_<版本>_x64-setup.exe`。
3. 在 GitHub 上建一个 **tag + Release**（tag 用 `v1.2.0` 这种形式），把上面那个安装包作为附件传上去。

更新检查会挑附件里最像安装包的那个（优先 `*_x64-setup.exe`，其次任意含 `setup` 的 exe）；如果某个 Release 没有附件，页面会提示你去 Release 页面手动下载。**注意**：更新包直接从 GitHub 下载，只靠 HTTPS 传输保护、没有做签名校验；如果需要签名校验，请改用 Tauri 官方 `tauri-plugin-updater` 并配置签名密钥（这样每次打包都需要 `TAURI_SIGNING_PRIVATE_KEY`，所以本项目默认没走这条路线）。

内置预设服务商（设置页可一键填充）：NVIDIA NIM、智谱 GLM、DeepSeek、阿里云百炼、OpenAI、硅基流动、Kimi、OpenRouter、Ollama、LM Studio、OpenCode Zen、百度千帆、腾讯混元、讯飞星火、Google Gemini、Groq、Mistral、xAI Grok、Together AI、DeepInfra、Cerebras、Fireworks —— 全部走 OpenAI 兼容协议。翻译页与「视觉大模型」识别页共用这一份清单：只有文本模型的服务商在识别页会标注「仅文本模型」并置灰，避免选了却用不了。

| 服务商 | 需要填写 | 申请地址 | 说明 |
| --- | --- | --- | --- |
| DeepL | API Key、账号类型 | deepl.com（账号 → API 密钥） | Free 密钥以 `:fx` 结尾 |
| 微软翻译（Azure） | API Key、区域 | portal.azure.com（创建「文本翻译」资源） | 区域例如 `eastasia`；每月有免费额度 |
| 谷歌翻译 | API Key | console.cloud.google.com（API 凭证） | Google Cloud Translation v2；密钥走 `X-Goog-Api-Key` 请求头，不放进 URL，建议在控制台限制该密钥 |
| 有道智云 | 应用 ID、应用密钥 | ai.youdao.com（控制台 → 应用总览） | 文本翻译 v3，签名走 `sha256`；**支持一步图片翻译** |
| 有道大模型翻译 | 应用 ID、应用密钥 | ai.youdao.com（控制台 → 应用总览 → 大模型翻译） | 「子曰」大模型通道，服务版本可选 **Pro / Lite**；接口是流式（SSE），程序自动取最终译文；需在控制台开通并充值 |
| 百度翻译 | AppID、密钥 | fanyi-api.baidu.com | 签名走 `md5`；**支持一步图片翻译**，服务版本可选通用文本 / 大模型；大模型版也可改用 **API Key（Bearer）** 鉴权，无需算签名 |
| 腾讯云翻译 | SecretId、SecretKey、区域（可选） | console.cloud.tencent.com（访问管理 → API 密钥） | 机器翻译 TMT，签名走 TC3-HMAC-SHA256，每月 500 万字符免费；**支持一步图片翻译** |

### 一步图片翻译（不做本地 OCR）

有道、百度、腾讯三家除了文本翻译接口，还提供「直接递交图片、一次拿回原文 + 译文」的接口。在设置页的 **「识别引擎」下拉**里直接选 **`由翻译渠道完成（一步图片翻译）`** 即可（前提是「翻译」页选的是这三家之一，页面会显示当前用的是哪家并提供申请入口）：

- 截图会**直接交给该服务商识别并翻译**，用不到本机 OCR（Windows 内置 OCR / 视觉大模型 / 本地服务），速度更快、排版还原更好；
- 这三家的图片翻译接口通常要在各自控制台**单独申请开通**，没开通时会返回未授权错误（百度返回 `52003`）；
- 该服务不可用时（未开通、超额、超时…）**会自动回退到「本机 OCR → 文本翻译」**，并在结果窗口提示「图片翻译失败，改用本机识别…」，不会白截一张图；
- 识别结果同样进历史记录，可以切换渠道重新翻译。

### 本地 OCR 服务（图片不出本机）

不想联网、又觉得 Windows 内置 OCR 对艺术字不够准，可以跑一个本机的开源 OCR 服务：设置页 **「识别引擎」选 `本地 OCR 服务`**，填上服务地址即可（默认 `http://127.0.0.1:1224`）。

推荐 [**Umi-OCR**](https://github.com/hiroi-sora/Umi-OCR/releases)（免费开源、解压即用、不写注册表）：

1. 下载并解压，双击 `Umi-OCR.exe` 启动；
2. 确认「全局设置 → 常规」里的 **HTTP 服务**是开启的（默认端口 `1224`，可改）；
3. 在 SnapLingo 设置页填同样的地址，点「检测服务」。

对接的是 Umi-OCR 的 `/api/ocr` 接口（`{"base64":…, "options":{"data.format":"text","tbpu.parser":"multi_para"}}`），因此任何兼容该协议的本地服务都能直接用；截图只在内存里编码成 base64 发给 `127.0.0.1`，不会离开你的电脑。

**百度翻译的「通用 / 大模型」档位**：百度有两条文本翻译通道，两条接口不同、需要在控制台各自开通。设置里可选：

| 档位 | 接口 | 说明 |
| --- | --- | --- |
| 通用文本翻译（默认） | `api/trans/vip/translate` | 兼容性最好的老接口，标准版 QPS 1、高级版 QPS 10，超出报 54003 |
| 大模型翻译 | `ait/api/aiTextTranslate` | 术语与语气更自然，需在控制台开通「大模型翻译」 |

腾讯云也提供两档：**大模型版翻译（默认，更准）** 与 **极速版（更快）**。有道则用同一套图片接口的 `translateOption` 参数区分（大模型结果 / 普通结果）。

**有道「大模型翻译」渠道**（独立于上面的有道智云文本翻译）：走 `proxy/http/llm-trans`，是**流式（SSE）接口**，程序用 `streamType=full` 收完整个流、取最后一条 `transFull` 作为译文；服务版本可选 **Pro（子曰翻译大模型）/ Lite（轻量版）**。它不提供图片翻译，因此「一步图片翻译」里不会出现它。

> 腾讯云图片翻译的免费额度与文本翻译共用；有道图片翻译按调用次数计费（3600 次/小时上限）；百度图片翻译的免费额度以控制台为准。

其他说明：图片递交前会**自动压到 3.5MB 以内**（先降质量再缩边），超过服务商限制会给出明确提示；返回的原文与译文会一并写入历史记录。

每一家服务商的 Key / 区域都**各存各的**（在 `profiles` 里各占一个条目）：

- **翻译渠道**：从 OpenRouter 换到微软翻译再换回来，两边的密钥都还在，也绝不会把 A 家的 Key 显示到 B 家的输入框里。
- **大模型厂商**：「大模型 · OpenAI 兼容」这一个渠道里可以选很多家厂商（NVIDIA、DeepSeek、智谱、OpenCode Zen、Groq…），**每家厂商也是一套独立的地址 + 模型 + 密钥**——切到 DeepSeek 就只看到 DeepSeek 的地址和 Key，切回 NVIDIA 还是原来那套。
- **视觉大模型**：识别页选「视觉大模型」时同样按厂商分开存（每个厂商一份地址 + 模型 + 密钥），另外保留一个「自定义」槽位。

旧版配置里扁平的 `translate.apiKey` / `ocr.apiKey` 等字段会在首次启动时自动迁入对应槽位（识别的那份进 `custom`），不会丢失。

> 云翻译引擎的目标语言支持范围由各家自己决定（例如有道/百度/腾讯对部分小语种有限制）。如果返回「不支持的语言」，换成该服务商支持的语言，或改用 OpenAI 兼容接口的 LLM 翻译即可。
>
> 目标语言可以设成 **`auto`（智能判断）**：原文主要是中文就译成英文，否则译成中文，中译英/英译中不用来回改设置。结果窗口底部的「目标语言」下拉也能随手切换——改完立即用缓存的原图重新翻译一次，并把这个选择记住给下一次截图。一步图片翻译（有道/百度/腾讯）在 `auto` 下会先按中文翻一次，若识别出的原文其实是中文，再用英文翻一次。

### 关于 API Key 的安全说明

API Key **以明文**保存在上述 `config.json` 中，仅依赖当前用户目录的访问控制（ACL）保护。
这不是加密存储：能读取当前用户文件的程序都可以读到它。请勿在共享电脑上保存长期密钥。

其它文件（同一目录）：

- `SnapLingo/snaplingo.log` —— 运行日志，超过 512KB 会在下次启动时清空。
- `SnapLingo/history.json` —— 历史记录；设置里可清空或关闭。
- `SnapLingo/config.json.bak` —— 当 `config.json` 解析失败时自动备份的坏文件。

## 技术链路

```
全局快捷键 / 托盘
      │
      ▼
capture（xcap + Windows Graphics Capture）
  先抓取全部显示器的完整帧，缓存在内存
      │
      ▼
为每块显示器创建一个无边框置顶 overlay 窗口，
把**冻结帧**铺满显示，前端只负责画蒙版和取框
      │
      ▼  user release → finish_selection(物理像素坐标)
从缓存帧裁切选区 → 图像预处理
  · 小图放大（长边目标 1400px，最多 3×，Lanczos3）
  · 大图降采样（长边上限 maxImageSide，CatmullRom）
  · 转 PNG（超 3.5MB 转 JPEG）→ base64
      │
      ▼
OCR：Windows.Media.Ocr（BGRA8 位图，离线）
     或 本地 OCR 服务（Umi-OCR 兼容 /api/ocr，图片不出本机）
     或 视觉大模型（image_url 传入，可一次返回译文）
     或 由云渠道直接读图（有道 / 百度 / 腾讯的一步图片翻译）
      │
      ▼
翻译：OpenAI 兼容 LLM / DeepL / 微软 / 谷歌 / 有道 / 百度 / 腾讯
（长文本按 ~2400 字符分块提交；每个请求最多重试 3 次，共 4 次尝试）
      │
      ▼
结果窗口（订阅 pipeline:stage / result:update 事件）
```

两条贯穿全链路的设计约束：

- **主线程永不阻塞**：截图、编码、OCR、网络全部跑在阻塞线程池或异步运行时；涉及窗口的命令都是 `async`。
- **失败必须被看见**：任何一步出错都会变成一张带原因的结果卡片 + 右下角一张应用内通知卡片（点击卡片打开日志页），并写进日志 —— 后台程序静默失败和坏掉是无法区分的。

启动后结果窗口与主显示器的选区窗口会被**预先创建并复用**，因此真正截图时窗口只需显示/隐藏/移动，不再创建 WebView（创建 WebView 是唯一可能让主线程卡住的昂贵操作）。

## 常见问题

**按下快捷键没反应**
快捷键被其它程序占用了。打开设置 → 通用 → 点击快捷键录制框重新录制一个组合；保存失败时会自动回滚并提示。

**识别结果是空的 / 乱码**
框选范围太小或文字太细。勾选「小图自动放大」，并把区域框得稍大一些（包含完整行）。中文竖排或艺术字识别率会下降。

**提示缺少 OCR 语言包**
系统没有安装对应语言的识别功能，按上文「系统要求」里的步骤添加语言并勾选光学字符识别。也可以改用「识别引擎」列表里的 `本地 OCR 服务` 或 `视觉大模型`，它们不依赖系统语言包。

**本地 OCR 服务连不上**
1. 确认服务已经启动（Umi-OCR 双击运行后托盘会有图标）；
2. 在 Umi-OCR「全局设置 → 常规」里确认 **HTTP 服务**已开启，端口与设置页填的一致（默认 `1224`）；
3. 地址要带 `http://` 前缀，例如 `http://127.0.0.1:1224`，点设置页的「检测服务」可验证；
4. 如果服务装在另一台机器上，把地址改成那台机器的 IP 并把 Umi-OCR 的监听地址设为 `0.0.0.0`（注意局域网内谁都能调用）。

**选了「由翻译渠道完成」却报未授权（如百度 52003）**
该渠道的「图片翻译」服务没有开通。去对应控制台单独申请开通，或把「识别引擎」换回 `Windows 内置 OCR` / `本地 OCR 服务` / `视觉大模型`（这三者不依赖云端的图片翻译服务）。调用失败时 SnapLingo 也会自动回退到本机识别 + 文本翻译。

**翻译报错 401 / 403**
接口地址或 Key 不对。设置页里点「测试连接」可快速定位；注意接口地址需要包含 `/v1` 这类版本前缀（如 `https://xxx/v1`）。

**想逐个渠道排查（推荐做法）**
1. 设置 → **翻译** 页，把「渠道」下拉切到要测的那家，填好凭据后点 **测试连接**（用一段示例文本走一次真实调用，会显示耗时与返回的译文）；
2. 失败就去 **日志** 页看那一行 `响应体（HTTP xxx）：…` —— 里面是服务商原样返回的内容，错误码、签名提示、配额说明都在里面（响应体的记录是新加的：以前只记状态码，看不出原因）；
3. **文本翻译**和**图片翻译**是两套接口：要验证图片翻译，需在**识别**页把「识别引擎」选成「由翻译渠道完成」，再按快捷键截一次图；
4. 「档位」（通用 / 大模型、Pro / Lite）可能对应**不同地址或不同参数**，设置页的「实际调用」提示、以及日志里的「本次任务」都会写明这次到底请求了哪个地址。

**翻译特别慢或超时**
单个请求超时 60 秒、最多重试 3 次（429 / 5xx / 网络错误），整体任务超过 150 秒会中止并提示「重试」。长文本会自动分块，代理/中转服务建议换成响应更快的模型。

**程序好像卡住了 / 选区窗口关不掉**
SnapLingo 有多层兜底，正常情况下不会卡住：
1. 再按一次快捷键，或托盘菜单「取消本次截图」；
2. 什么都不做，3 分钟后选区会自行取消；
3. 若主线程真的无响应（连上面两步都失效），程序会在 4 分钟后自动退出，请在托盘重新启动。

**想知道某次执行走了哪个渠道 / 调了哪个地址**
托盘菜单「查看日志…」或设置 → **日志** 页：每次执行都会先写一行「本次任务」摘要（识别渠道、翻译渠道、两个接口的 方法 + 地址、图片大小），随后记录接口响应状态与失败原因。日志用 **本地时间**，**最新的在最上面**，可以按 **错误 / 警告 / 信息 / 调试** 类型筛选（失败一律记为「错误」），设置页的 OCR / 翻译卡片下方也会实时显示 **实际调用** 的地址（含「通用文本翻译 / 大模型翻译」这类档位说明），方便和官方文档对照。

每次失败都会写入 `%APPDATA%\SnapLingo\snaplingo.log`（启动时若超过 512 KB 会清空重开，设置页只读取文件末尾 256 KB，所以旧记录不会被无限加载），反馈问题时附上该文件即可。

**多显示器下选区错位**
SnapLingo 按显示器的物理像素创建窗口与换算坐标，支持不同的缩放比例（DPI）混合环境。如遇错位，请在设置里把窗口模式改为「只截鼠标所在显示器」并反馈日志。
